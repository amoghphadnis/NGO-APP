PAYANA STUDENTS API CONTRACT DOCUMENT

=========================================================
BASE ROUTE / ROUTE PREFIX
=========================================================

Base Route:
api/payanastudents

Controller:
PayanaStudentsApiController

API Description:
This API provides functionality to:
1. Create a new Payana Student application.
2. Load all master dropdown data required by the Payana Student application form.
3. Retrieve the approved Payana Student list.
4. Retrieve the District dropdown independently.

Authentication:
- The controller itself does not have [JwtSessionFilter] at controller level.
- The CREATE endpoint does not explicitly require JWT authentication in the supplied code.
- The DROPDOWNS endpoint does not explicitly require JWT authentication in the supplied code.
- The STUDENT LIST endpoint explicitly applies [JwtSessionFilter] and therefore requires authenticated JWT/session information.
- The DISTRICTS endpoint does not explicitly require JWT authentication in the supplied code.
- For authenticated requests, CurrentUser.Role and CurrentUser.UserID are used by the Student List endpoint.

Important:
The exact JWT header format, token expiry, token issuer, and token signing details are not defined in this controller and must be documented separately based on JwtSessionFilter implementation.

=========================================================
1. CREATE PAYANA STUDENT
=========================================================

Endpoint:
POST /api/payanastudents/create

Purpose:
Creates and submits a new Payana Student application.

The endpoint:
- Accepts student application data.
- Accepts optional uploaded documents/images using multipart/form-data.
- Validates that StudentName is supplied.
- Checks whether the submitted Email already exists in PayanaStudents.
- Rejects duplicate email registrations with HTTP 409 Conflict.
- Saves uploaded files to the ~/Uploads/ folder.
- Generates a unique GUID-based filename for each uploaded file.
- Stores the generated relative file paths in the PayanaStudents table.
- Inserts the student application into the PayanaStudents table.
- Returns a success response after successful database insertion.

Content-Type:
multipart/form-data

Authorization:
Not explicitly required by the supplied controller code.

- Because the SQL query compares LOWER(Email) with LOWER(@Email), the actual database behavior for a null Email depends on existing database records and SQL NULL comparison semantics.
- No explicit email format validation is implemented.
- No explicit phone number validation is implemented.
- No explicit numeric range validation is implemented.

Validation Rules:
- StudentName is mandatory.
- StudentName must not be null, empty, or whitespace.
- No minimum length is explicitly enforced for StudentName.
- No maximum length is explicitly enforced for StudentName.
- Email is checked for duplicate registration.
- Email comparison is case-insensitive using LOWER(Email) = LOWER(@Email).
- Duplicate email results in HTTP 409 Conflict.
- Email format is not validated by the controller.
- All other model fields are nullable from the controller's perspective.
- Missing nullable values are passed to SQL as DBNull.Value.
- File fields are optional.
- Files with ContentLength greater than 0 are saved.
- Empty or missing files are ignored.
- File extension validation is not implemented.
- File size validation is not implemented.
- MIME type validation is not implemented.
- No explicit validation of foreign key IDs is implemented in the controller.
- No explicit validation of bank account number or IFSC format is implemented.
- No explicit validation of contact number format is implemented.
- No explicit validation of percentage ranges is implemented.
- No explicit validation of income/fees/expense ranges is implemented.

Business Logic Notes:
- The endpoint inserts a record into PayanaStudents.
- StudentName is the only field explicitly required by the controller.
- Email uniqueness is checked before insertion.
- Duplicate email returns HTTP 409 Conflict with:
  "This Email ID is already registered. Student can apply only once."
- The duplicate email check is case-insensitive.
- Uploaded files are stored with GUID-based names to reduce filename collision risk.
- The original file extension is retained.
- The API stores relative upload paths rather than physical server paths.
- No application status is explicitly set by this controller during INSERT.
- No approval status is explicitly assigned during creation.
- No role-based creation logic is implemented.
- No authenticated user ID is stored by this controller.
- No transaction is used across file saving and database insertion.
- If files are successfully saved but the database INSERT later fails, the uploaded files may remain on disk without a corresponding database record.
- If database insertion succeeds, the API returns a generic success response.
- The API does not return the newly generated StudentID.
- The API does not return the uploaded file URLs individually.

3. GET PAYANA STUDENT LIST
=========================================================

Endpoint:
GET /api/payanastudents/studentlist

Purpose:
Returns the list of approved Payana Students assigned to the logged-in volunteer or filtered by district for non-volunteer users.

Optional examples:
GET /api/payanastudents/studentlist
GET /api/payanastudents/studentlist?search=Rahul
GET /api/payanastudents/studentlist?districtId=1
GET /api/payanastudents/studentlist?search=Rahul&districtId=1

The endpoint also determines whether a House Visit exists for each student and returns the corresponding House Visit approval status.

Content-Type:
application/json

Authorization:
Required.

This endpoint explicitly uses:
[JwtSessionFilter]

The authenticated JWT/session must provide the user information required by:
- CurrentUser.Role
- CurrentUser.UserID

Path Parameters:

| Name | Type | Required | Description |
|------|------|----------|-------------|
| None | - | No | This endpoint has no path parameters. |

Query Parameters:

| Name | Type | Required | Description |
|------|------|----------|-------------|
| search | string | No | Filters students by StudentName using SQL LIKE matching. The supplied value is surrounded by % characters. |
| districtId | integer | No | Filters students by DistrictID for non-volunteer users. This filter is ignored when the logged-in user's role is Volunteer. |

Request Body:
None.

Form Data / Multipart Fields:

| Field | Type | Required | Description |
|------|------|----------|-------------|
| None | - | No | This endpoint does not accept form data. |

File Upload Fields:

| Field | Type | Required | Allowed Extensions | Max Size |
|------|------|----------|--------------------|----------|
| None | - | No | N/A | N/A |

Validation Rules:
- JWT/session authentication is required through JwtSessionFilter.
- search is optional.
- districtId is optional.
- If search is null, empty, or whitespace, no search filter is applied.
- If search is supplied, whitespace is not explicitly trimmed before creating the SQL LIKE parameter.
- If districtId is supplied and the user is not a Volunteer, the district filter is applied.
- If the user role is Volunteer, districtId is ignored.
- Student records are returned only when PayanaStudents.ApproveStatus = 'Approved'.
- StudentID is mapped from the PayanaStudents table.
- FamilyIncome is nullable.
- SecuredPercentage is nullable.
- HouseVisitLink is nullable.
- DistrictName is nullable.
- CollegeName is nullable.
- ApproveStatus is nullable.
- IsVisited is represented as a Boolean.
- No explicit maximum length validation is performed on search.
- No explicit numeric range validation is performed on districtId.
- No explicit validation is performed to verify that districtId exists in DistrictMaster.

Business Logic Notes:
- The endpoint reads the logged-in user's role from CurrentUser.Role.
- If CurrentUser.Role == "Volunteer":
  - The query is restricted to sva.VolunteerID = CurrentUser.UserID.
  - districtId is ignored.
- If CurrentUser.Role is not "Volunteer":
  - The API allows districtId filtering when districtId is supplied.
- The comparison for role is case-sensitive because the code uses:
  role == "Volunteer"
- Only approved Payana Students are returned.
- The student assignment table is:
  Payana_StudentVolunteerAssignment
- Student data is loaded from:
  PayanaStudents
- District name is loaded from:
  DistrictMaster
- House visit information is loaded from:
  HouseVisitForm
- IsVisited is true when a matching HouseVisitForm record exists for the student.
- IsVisited is false when no matching HouseVisitForm record exists.
- HouseVisitForm.ApproveStatus is returned as ApproveStatus.
- Student data is returned in the PayanaStudentListVM structure.
- The response wraps the list inside ApiSuccessResponse.
- No pagination is implemented.
- No sorting/order by clause is explicitly defined.
- Duplicate records may potentially occur if multiple assignment or house visit rows exist for the same student, depending on database relationships.

=========================================================
API ENDPOINT SUMMARY
=========================================================

| # | HTTP Method | Endpoint | Authentication | Purpose |
|---|-------------|----------|----------------|---------|
| 1 | POST | /api/payanastudents/create | Not explicitly required | Creates a Payana Student application with optional file uploads. |
| 2 | GET | /api/payanastudents/dropdowns | Not explicitly required | Returns all Payana application dropdown/master data. |
| 3 | GET | /api/payanastudents/studentlist | JWT/session required | Returns approved Payana students with role-based volunteer/district filtering. |
| 4 | GET | /api/payanastudents/districts | Not explicitly required | Returns the District dropdown list. |

=========================================================
IMPORTANT IMPLEMENTATION NOTES
=========================================================

1. The Create endpoint accepts multipart/form-data because it reads uploaded files from HttpContext.Current.Request.Files.

2. The Create endpoint's method signature receives PayanaStudentViewModel model, while uploaded files are separately obtained from HttpContext.Current.Request.Files.

3. The Create endpoint only explicitly validates StudentName.

4. All other form fields are effectively optional from the controller's perspective.

5. The Create endpoint does not explicitly set a default ApproveStatus.

6. The Create endpoint does not explicitly set an application status.

7. The Create endpoint does not return the newly created StudentID.

8. The Create endpoint does not use a database transaction covering both file storage and database insertion.

9. File extension, MIME type, and file size restrictions are not implemented in the supplied controller.

10. The Student List endpoint is the only endpoint in this controller that explicitly has [JwtSessionFilter].

11. For Student List:
    - Volunteer users are restricted to their own assigned students.
    - Volunteer users cannot use districtId to broaden/filter the result.
    - Non-volunteer users can filter by districtId when supplied.
    - Only students whose PayanaStudents.ApproveStatus equals "Approved" are returned.

12. The Student List endpoint uses case-sensitive role comparison:
    role == "Volunteer"

13. The Student List endpoint returns an empty list with HTTP 200 if no students match the filters.

14. The Districts endpoint returns an empty Data array with HTTP 200 if no district records are found.

15. The Dropdowns endpoint returns multiple independent master lists in a single response.

16. FatherOccupationMaster and MotherOccupationMaster are filtered using Status = 1.

17. The other dropdown master queries do not use a Status filter.

18. The exact DTO property types and nullable annotations for PayanaStudentViewModel, PayanaStudentListVM, DropdownDto, PayanaDropdownResponse, ApiSuccessResponse, and ApiErrorResponse should be verified against their actual model definitions before publishing this contract as a strict OpenAPI/Swagger specification.

19. The exact authentication header format and JWT behavior should be verified from JwtSessionFilter and related JWT authentication code.

20. The following response fields are case-sensitive according to the C# JSON serialization configuration in use:
    - Success
    - Message
    - Data
    - StudentID
    - StudentName
    - ContactNumber
    - Address
    - PinCode
    - HouseVisitLink
    - Taluka
    - DistrictName
    - CollegeName
    - FamilyIncome
    - SecuredPercentage
    - IsVisited
    - ApproveStatus
