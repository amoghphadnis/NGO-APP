API CONTRACT DOCUMENT
Controller: HouseVisitController
Base Route: /api/housevisit
Technology: ASP.NET Web API 2 / ADO.NET
GENERAL NOTES
This controller exposes two endpoints using the same route /api/housevisit/create: GET loads the student context and POST submits the house visit.
The POST endpoint supports PUC, Payana, and Professional sources and dynamically selects the corresponding main and family-member tables.
No [Authorize] attribute or explicit authentication/token check is present in the supplied controller. Authorization is therefore documented as Not Required by this controller.
1. Create House Visit Form - Get Student Details
Endpoint: GET /api/housevisit/create
Purpose: Retrieves the student name for the selected source and initializes the house-visit form.
Content-Type: application/json
Authorization: Not Required
Path Parameters
Name	Type	Required	Description
None	-	No	No path parameters.
Query Parameters
Name	Type	Required	Description
studentId	integer	Yes	Student identifier. For Professional, this is matched to ApplicationID.
source	string	Yes	Allowed values: PUC, Payana, Professional. Case-insensitive.
Request Body
None. Parameters are supplied in the query string.
Example: GET /api/housevisit/create?studentId=1&source=PUC
Validation Rules
•	studentId must be greater than 0.
•	source is required and cannot be blank.
•	source is trimmed before processing.
•	Allowed values are PUC, Payana, and Professional; comparison is case-insensitive.
•	PUC queries New_Students.StudentID.
•	Payana queries PayanaStudents.StudentID.
•	Professional queries NewProfessionalApplication.ApplicationID.
•	No matching record returns 404.
Business Logic Notes
•	For Professional, the parameter named studentId represents ApplicationID.
•	The response returns StudentID, StudentName, and the normalized Source.
Success Response (200)
{
  "studentID": 1,
  "studentName": "John Doe",
  "source": "PUC"
}
Failure Responses
Status	Condition	Example
400 Bad Request	Invalid Student ID	{"success":false,"message":"Invalid Student ID."}
400 Bad Request	Source missing	{"success":false,"message":"Source is required."}
400 Bad Request	Invalid source	{"success":false,"message":"Invalid Source. Allowed values are PUC, Payana and Professional."}
404 Not Found	Student not found	{"success":false,"message":"Student not found."}
500 Internal Server Error	Unexpected error	{"success":false,"message":"Error message"}
401 Unauthorized: Not explicitly generated by this controller.
403 Forbidden: Not explicitly generated by this controller.
409 Conflict: Not explicitly generated by this controller.
Status Codes Used: 200, 400, 404, 500

Validation Rules
•	Request must be multipart/form-data.
•	source is required.
•	Allowed source values: PUC, Payana, Professional.
•	StudentID must be greater than 0.
•	FamilyMembers is optional; if supplied, invalid JSON returns 400.
•	HousePhoto is optional; if supplied, only JPG, JPEG, and PNG are accepted.
•	UploadedFile is optional and may contain multiple files.
•	No maximum file size is enforced in the supplied controller.
•	No explicit string min/max lengths are enforced.
•	Blank strings are generally converted to null.
•	Invalid date values become null rather than generating a validation error.
•	Status is automatically set to 1.
Business Logic Notes
•	PUC: main table HouseVisitForm_PUC; key column PUC_StudentID; family table HouseVisitFamilyMembers.
•	Payana: main table HouseVisitForm; key column StudentID; family table PayanaFamilyMembers.
•	Professional: main table HouseVisitForm_Professional; key column ApplicationID; family table ProfessionalFamilyMembers.
•	Main insert and family-member inserts execute inside one SQL transaction.
•	Any database failure rolls back the transaction.
•	HouseVisitID is obtained using SCOPE_IDENTITY().
•	UploadedFile files are stored under ~/HouseDocUploads and their generated names are comma-separated in Upload.
•	HousePhoto files are stored under ~/HouseDocUploads/HousePhoto.
•	HousePhoto is renamed with a GUID and its extension.
•	Status defaults to 1.
•	VolunteerApprovalStatus comes from the request and has no automatic default.
•	RedirectController is PUC_StudentsList, PayanaStudents, or Professional_StudentList depending on source.
•	RedirectAction is always StudentList.
