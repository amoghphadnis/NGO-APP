=========================================================
1. PUC STUDENT LIST
=========================================================

Endpoint:
GET /api/pucstudents/studentlist

Purpose:
Retrieves a list of approved PUC students accessible to the authenticated user.

The API:
- Returns only students whose New_Students.ApprovalStatus = 'Approved'.
- Supports optional student-name searching.
- Supports optional district filtering.
- Restricts Volunteer users to students assigned to the logged-in Volunteer.
- Ignores districtId filtering for Volunteer users.
- Allows non-Volunteer users to filter by the supplied districtId.
- Includes house visit information.
- Indicates whether a house visit record exists.
- Returns house visit approval status.
- Includes a complete district dropdown list in the same response.
- Orders the district dropdown alphabetically by DistrictName.

Content-Type:
application/json

Authorization:
Required - JWT authentication/token required.

Authentication Filter:
JwtSessionFilter

Required Authenticated User Context:
- CurrentUser.Role
- CurrentUser.UserID

Path Parameters:

|------|------|----------|-------------|
| None | - | No | This endpoint does not use path parameters. |

Query Parameters:

|------|------|----------|-------------|
| search | string | No | Optional student-name search value. If supplied and not null, empty, or whitespace-only, the value is trimmed and used in a SQL LIKE search against StudentName. |
| districtId | integer | No | Optional district ID filter. Applied only when the authenticated user's role is not Volunteer. Ignored for Volunteer users. |

Request Body:
None.

This endpoint is a GET request and does not accept a JSON request body.

Full JSON Request Body Sample:

=========================================================
VALIDATION RULES
=========================================================

1. search is optional.

2. search defaults to null when not supplied.

3. districtId is optional.

4. districtId defaults to null when not supplied.

5. If search is null, empty, or contains only whitespace:
   - No StudentName search condition is added.

6. If search contains a value:
   - Leading and trailing whitespace is removed using Trim().
   - The resulting value is searched using:
     s.StudentName LIKE @Search

7. The actual SQL search parameter is:
   "%" + search.Trim() + "%"

8. No explicit minimum length validation is implemented for search.

9. No explicit maximum length validation is implemented for search.

10. districtId must be supplied as a nullable integer when provided.

11. No explicit validation is performed to verify that districtId exists in DistrictMaster.

12. No explicit validation is performed to verify that districtId belongs to the authenticated user.

13. For Volunteer users:
    - districtId is ignored even when supplied.
    - The API uses CurrentUser.UserID as the VolunteerID.

14. For non-Volunteer users:
    - If districtId is supplied, it is applied as a student DistrictID filter.

15. Only students where:
    New_Students.ApprovalStatus = 'Approved'
    are returned.

16. StudentID is converted directly using Convert.ToInt32().
    - The controller does not explicitly handle NULL StudentID values.
    - Therefore, StudentID is expected to be non-null in the database.

17. StudentName:
    - Nullable in the response.
    - Database NULL becomes null.

18. ContactNumber:
    - Nullable in the response.
    - Database NULL becomes null.

19. Address:
    - Nullable in the response.
    - Database NULL becomes null.

20. Place:
    - Nullable in the response.
    - Database NULL becomes null.

21. Taluka:
    - Nullable in the response.
    - Database NULL becomes null.

22. PinCode:
    - Nullable in the response.
    - Database NULL becomes null.

23. HouseVisitLink:
    - Nullable in the response.
    - Database NULL becomes null.

24. DistrictName:
    - Nullable in the response.
    - Database NULL becomes null.

25. CollegeName:
    - Nullable in the response.
    - Database NULL becomes null.

26. FamilyIncome:
    - Nullable decimal.
    - Database NULL becomes null.

27. SecuredPercentage:
    - Nullable decimal.
    - Database NULL becomes null.

28. IsVisited:
    - Boolean.
    - Returns true when a matching HouseVisitForm_PUC record exists.
    - Returns false when no matching house visit record exists.

29. ApproveStatus:
    - Nullable string.
    - Maps from HouseVisitForm_PUC.ApproveStatus.
    - Database NULL becomes null.

30. No pagination is implemented.

31. No page number parameter is implemented.

32. No page size parameter is implemented.

33. No dynamic sorting parameter is implemented.

34. The student query itself does not contain an ORDER BY clause.
    - Therefore, the order of student records is not explicitly guaranteed by the SQL query.

35. District dropdown records are explicitly sorted by:
    ORDER BY DistrictName

=========================================================
BUSINESS LOGIC NOTES
=========================================================

1. APPROVED STUDENT FILTER:
   The API only returns records where:

   s.ApprovalStatus = 'Approved'

   IMPORTANT:
   The PUC student approval status used for filtering comes from:
   New_Students.ApprovalStatus

2. VOLUNTEER ROLE FILTER:
   If:

   CurrentUser.Role equals "Volunteer"

   using a case-insensitive comparison,

   then the API adds:

   AND sva.VolunteerID = @VolunteerID

   where:

   @VolunteerID = CurrentUser.UserID

3. VOLUNTEER DISTRICT FILTER:
   The districtId query parameter is completely ignored for Volunteer users.

   Therefore:

   Request:
   GET /api/pucstudents/studentlist?districtId=5

   If authenticated user is Volunteer:

   districtId = 5

   has no effect on the SQL query.

4. NON-VOLUNTEER DISTRICT FILTER:
   If the authenticated user is not a Volunteer and districtId is supplied:

   AND s.DistrictID = @DistrictID

   is added to the query.

5. CLIENT CANNOT OVERRIDE VOLUNTEER ID:
   VolunteerID is never accepted as a query parameter.

   The API derives VolunteerID from:

   CurrentUser.UserID

6. CLIENT CAN SUPPLY DISTRICT FILTER:
   Unlike the SemiProfessional controller pattern, this controller accepts districtId directly from the client.

   However, the district filter is still restricted by role:
   - Volunteer: ignored
   - Non-Volunteer: applied when supplied

7. SEARCH LOGIC:
   If search is supplied:

   AND s.StudentName LIKE @Search

   where:

   @Search = "%" + search.Trim() + "%"

8. STUDENT APPROVAL:
   The Student List is restricted to:

   New_Students.ApprovalStatus = 'Approved'

9. HOUSE VISIT LOGIC:
   House visit data is retrieved using:

   HouseVisitForm_PUC

   with:

   hv.PUC_StudentID = s.StudentID

10. IS VISITED LOGIC:
    IsVisited is calculated using:

    CASE
        WHEN hv.PUC_StudentID IS NOT NULL
        THEN 1
        ELSE 0
    END

    API mapping:
    - 1 = true
    - 0 = false

11. HOUSE VISIT APPROVAL STATUS:
    The API response field ApproveStatus maps to:

    HouseVisitForm_PUC.ApproveStatus

    IMPORTANT:
    This is separate from the student approval filter:

    Student approval filter:
    New_Students.ApprovalStatus

    Response ApproveStatus:
    HouseVisitForm_PUC.ApproveStatus

12. DISTRICT INFORMATION:
    DistrictName is retrieved from:

    DistrictMaster

    using:

    s.DistrictID = d.DistrictID

13. DISTRICT DROPDOWN:
    The API calls the private LoadDistricts() method after retrieving the student list.

14. DISTRICT DROPDOWN SOURCE:
    DistrictMaster

15. DISTRICT DROPDOWN ORDER:
    DistrictName ascending.

16. EMPTY STUDENT RESULT:
    If no students match the applied filters, the API is expected to return HTTP 200 with:

    "Students": []

    provided no exception occurs.

17. DUPLICATE RECORD POSSIBILITY:
    The SQL query directly joins:
    - StudentVolunteerAssignment
    - HouseVisitForm_PUC

    If multiple assignment or house visit records exist for the same student, duplicate student rows may be returned.

    The controller does not use:
    - DISTINCT
    - GROUP BY
    - Duplicate removal
    - Deduplication logic

18. DATABASE CONNECTION:
    The API uses:

    ConfigurationManager.ConnectionStrings["EnvisageDb"]

=========================================================
SQL JOIN LOGIC
=========================================================

Primary Student Query:

SELECT
    s.StudentID,
    s.StudentName,
    s.ContactNumber,
    s.Address,
    s.Place,
    s.Taluka,
    s.PinCode,
    s.HouseVisitLink,
    d.DistrictName,
    s.CollegeName,
    s.FamilyIncome,
    s.SecuredPercentage,
    sva.VolunteerID,
    hv.ApproveStatus,

    CASE
        WHEN hv.PUC_StudentID IS NOT NULL
        THEN 1
        ELSE 0
    END AS IsVisited

FROM StudentVolunteerAssignment sva

INNER JOIN New_Students s
    ON s.StudentID = sva.StudentID

LEFT JOIN DistrictMaster d
    ON s.DistrictID = d.DistrictID

LEFT JOIN HouseVisitForm_PUC hv
    ON hv.PUC_StudentID = s.StudentID

WHERE s.ApprovalStatus = 'Approved'


DYNAMIC FILTERS:

Volunteer:
AND sva.VolunteerID = @VolunteerID

Search:
AND s.StudentName LIKE @Search

Non-Volunteer District:
AND s.DistrictID = @DistrictID


PARAMETER VALUES:

@VolunteerID:
CurrentUser.UserID

@Search:
"%" + search.Trim() + "%"

@DistrictID:
districtId.Value

| Any authenticated user | s.ApprovalStatus = 'Approved' |
| search supplied | s.StudentName LIKE '%' + search.Trim() + '%' |

SECURITY NOTES
=========================================================

1. JWT authentication is expected through JwtSessionFilter.

2. Volunteer users cannot specify another VolunteerID because VolunteerID is not accepted as a query parameter.

3. Volunteer filtering is performed server-side using CurrentUser.UserID.

4. The districtId parameter is accepted directly from the client for non-Volunteer users.

5. Volunteer users cannot use districtId to alter their result set because the parameter is ignored for Volunteers.

6. The controller does not explicitly implement an Admin-only authorization rule.

7. The controller does not define a list of allowed roles.

8. Any role other than "Volunteer" follows the non-Volunteer district-filtering branch.

9. SQL parameters are used for:
   - VolunteerID
   - Search
   - DistrictID

10. The user-provided search value is passed through the @Search SQL parameter rather than directly concatenated into the SQL query.

11. Raw exception messages are currently returned in HTTP 500 responses.

12. For production security, detailed exception messages should be logged server-side and replaced with a generic API error message.
