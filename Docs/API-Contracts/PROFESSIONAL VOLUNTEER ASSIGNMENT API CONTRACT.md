=========================================================

PROFESSIONAL VOLUNTEER ASSIGNMENT API CONTRACT

============

API Name:

Professional Volunteer Assignment API

API BASE ROUTE

==============

Route Prefix:

/api/professional-volunteer-assignment

Authentication:

JWT authentication is applied at ACTION LEVEL in the supplied controller through [JwtSessionFilter].

Important:

- The controller itself does NOT have a controller-level [JwtSessionFilter].

- Therefore, authentication is not automatically applied to the entire controller.

- However, every endpoint currently defined in this controller has [JwtSessionFilter].

- Accordingly, all endpoints in the supplied controller currently require JWT authentication.

- The controller does not contain [Authorize] or another role attribute.

- The Volunteer role receives additional district-based authorization checks in the students and volunteers endpoints.

- JWT claims themselves are not directly read by this controller. Instead, the controller reads UserRole and DistrictID from HttpContext.Current.Session. Therefore, the JWT/session integration must populate these Session values before the protected endpoints are called.

2. GET STUDENTS BY DISTRICT

=========================================================

Endpoint:

GET /api/professional-volunteer-assignment/students?districtId={districtId}

Purpose:

Retrieves approved Professional students for a specified district from both:

1. NewProfessionalApplication

2. GoogleSheet\_NewProfessional

The endpoint also returns:

- student information

- family income

- PU percentage

- CET/NEET rank

- remark

- assigned volunteer

- assignment status

- house visit completion status for New Student records

Content-Type:

application/json

Authorization:

\* JWT Required

\* JWT Filter: [JwtSessionFilter]

\* Filter Scope: Action-level

\* Required Role: No fixed role is declared.

\* Additional Volunteer authorization is implemented in the controller.

JWT / Authorization Details:

\* JWT Required: Yes

\* Filter/Authorization Scope: Action-level

\* Required Claims: Not directly specified.

\* Required Roles: No single role is required by the endpoint.

\* Special role behavior: If the authenticated user's Session["UserRole"] is "Volunteer", the user is restricted to the district stored in Session["DistrictID"].

\* Session values used:

- Session["UserRole"]

- Session["DistrictID"]

\* JWT claims are not directly read by the action.

\* The JWT/session filter is expected to establish the required authenticated session context.

Path Parameters:

| Name | Type | Required | Description |

|------|------|----------|-------------|

| None | - | - | District ID is supplied as a query parameter, not a path parameter. |

Query Parameters:

| Name | Type | Required | Description |

|------|------|----------|-------------|

| districtId | int | Yes | District ID used to filter Professional students. Must be greater than 0. |

Request Body:

None.

Request Example:

GET /api/professional-volunteer-assignment/students?districtId=5

Validation Rules:

\* districtId is required.

\* districtId must be greater than 0.

\* If districtId <= 0, the API returns 400 Bad Request.

\* If the authenticated user's role is Volunteer:

- Session["DistrictID"] must exist and be a valid integer.

- The requested districtId must exactly match Session["DistrictID"].

\* A Volunteer attempting to access another district receives 403 Forbidden.

\* A Volunteer without Session["DistrictID"] receives 403 Forbidden.

\* Authentication/filter validation is handled by [JwtSessionFilter].

\* No pagination parameters are supported.

\* No search parameters are supported.

\* No sorting parameters are supported.

\* No date filtering is supported.

Business Logic Notes:

1. Role-based district restriction:

If:

Session["UserRole"] = "Volunteer"

then:

- Session["DistrictID"] must be available.

- Requested districtId must equal Session["DistrictID"].

Otherwise:

- The request is rejected with 403 Forbidden.

2. New Student records:

Records are retrieved from NewProfessionalApplication.

Conditions:

s.ApproveStatus = 'Approved'

AND s.DistrictID = @DistrictID

3. Google Sheet records:

Records are retrieved from GoogleSheet\_NewProfessional.

Conditions:

gp.Approve = 'Approved'

AND dm.DistrictID = @DistrictID

4. Volunteer assignment:

For New Student records:

Professional\_StudentVolunteerAssignment.StudentID is matched against ApplicationID.

For Google Sheet records:

Professional\_StudentVolunteerAssignment.ImportID is matched against ImportID.

5. Assigned status:

For New Student:

IsAssigned = 1 when a matching StudentID exists in Professional\_StudentVolunteerAssignment; otherwise 0.

For Google Sheet:

IsAssigned = 1 when a matching ImportID exists in Professional\_StudentVolunteerAssignment; otherwise 0.

6. Volunteer display:

The volunteer name is returned as:

Volunteer Name + " (" + Volunteer District + ")"

For example:

"John Doe (Dharwad)"

7. House visit status:

For New Student records:

A student is considered to have completed a house visit when a matching record exists in HouseVisitForm\_Professional with:

Professional\_StudentID = ApplicationID

AND Status = 1

Then:

IsHouseVisitCompleted = 1

Otherwise:

IsHouseVisitCompleted = 0

For Google Sheet records:

IsHouseVisitCompleted is always returned as 0.

8. CET/NEET rank:

If CETRank exists:

"CET: {value}"

If NEETRank exists:

"NEET: {value}"

If both exist:

"CET: {value} | NEET: {value}"

If neither exists:

""

9. Source values:

The SQL query explicitly returns:

- "New Student"

- "Google Sheet"

10. Approved records only:

Unapproved records are excluded.

Database Behavior:

Tables accessed:

Operations:

SELECT only.

No INSERT, UPDATE, or DELETE occurs.

DistrictMaster

Professional\_StudentVolunteerAssignment

Users

DistrictMaster for volunteer district

Google Sheet query joins:

GoogleSheet\_NewProfessional

DistrictMaster

Professional\_StudentVolunteerAssignment

Users

IMPORTANT IMPLEMENTATION NOTES

==============================

1. JWT scope

There is no controller-level [JwtSessionFilter].

The filter is explicitly attached to each of the seven actions.

Therefore, the current implementation requires JWT authentication for every endpoint in this controller.

2. Session-based authorization

The students and volunteers actions read:

HttpContext.Current.Session["UserRole"]

and:

HttpContext.Current.Session["DistrictID"]

The controller does not itself extract UserID, EmployeeID, Role, or DistrictID from JWT claims.

Therefore, the exact JWT claim names cannot be documented from this controller.

The authentication architecture must ensure that JwtSessionFilter or another authentication component establishes these Session values.

3. Volunteer district restriction

For students and volunteers:

If UserRole is Volunteer:

- DistrictID must exist in Session.

- Requested districtId must equal Session DistrictID.

4. No explicit Admin/Branch Executive role check

The controller does not explicitly require:

- Admin

- Branch Executive

- District Executive

- Employee

- any other named role

for assign, reassign, or cancel.

Therefore, those roles must NOT be documented as required roles based solely on this controller.

5. Assignment table behavior

Professional\_StudentVolunteerAssignment is used for both source types.

New Student:

StudentID identifies the assignment.

Google Sheet:

ImportID identifies the assignment.

6. Cancel endpoint HTTP method

The controller uses:

[HttpPost]

[Route("cancel")]

Therefore the correct API method is POST, not DELETE.

7. House visit status

Only New Student records check HouseVisitForm\_Professional.

Google Sheet records always return:

IsHouseVisitCompleted = 0

8. Approval filtering

New Student:

ApproveStatus = 'Approved'

Google Sheet:

Approve = 'Approved'

9. No pagination

None of the GET endpoints supports page number or page size.

10. No file upload

No endpoint accepts multipart/form-data.

11. No explicit duplicate handling

The controller does not check whether an assignment already exists before INSERT.

Any database constraint error is caught by the generic exception handler and returned as HTTP 500.

12. No explicit transaction

Assign, reassign, and cancel operations do not create an explicit SQL transaction.

13. No audit fields

The controller does not populate CreatedBy, ModifiedBy, CreatedDate, ModifiedDate, UserID, or EmployeeID.

14. No soft delete

CancelAssignment performs a direct DELETE against:

Professional\_StudentVolunteerAssignment

15. Error exposure

The controller returns:

ex.Message

in 500 responses.

Therefore, the actual exception message may be exposed to the API client.

16. Null handling

The controller explicitly converts several database NULL values to null or nullable decimal values.

For example:

- StudentName

- ContactNumber

- DistrictName

- FamilyIncome

- PUPercentage

- VolunteerName

- Remark

17. District matching for Google Sheet students

GoogleSheet\_NewProfessional.District is matched against DistrictMaster.DistrictName using:

LTRIM(RTRIM(gp.District)) =

LTRIM(RTRIM(dm.DistrictName))

The resulting DistrictID is then compared with @DistrictID.

18. Volunteer district lookup

Volunteer display information is derived through:

Users.DistrictID -> DistrictMaster.DistrictID

19. Volunteer dropdown filtering

The volunteer list uses Users.District, which is compared to the DistrictMaster DistrictName obtained from the requested DistrictID.

20. No public endpoint

Although some endpoints are read-only dropdown/list APIs, they are NOT public in the supplied implementation because [JwtSessionFilter] is present on each action.
