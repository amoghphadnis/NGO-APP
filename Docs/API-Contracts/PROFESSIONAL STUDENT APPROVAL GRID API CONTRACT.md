API BASE ROUTE

==============

Route Prefix:

/api/professional-student-approval

Authentication:

JWT authentication is NOT applied at controller level.

Authentication is applied individually at action level:

1. GET /api/professional-student-approval/index

- JWT Required: No

2. GET /api/professional-student-approval/list

- JWT Required: Yes

- Existing attribute: [JwtSessionFilter]

3. POST /api/professional-student-approval/approve/{id}

- JWT Required: Yes

- Existing attribute: [JwtSessionFilter]

4. POST /api/professional-student-approval/reject/{id}

- JWT Required: Yes

- Existing attribute: [JwtSessionFilter]

5. POST /api/professional-student-approval/delete/{id}

- JWT Required: Yes

- Existing attribute: [JwtSessionFilter]

No controller-level JWT filter or [Authorize] attribute is present.

Important:

The controller uses HttpContext.Current.Session["UserRole"] and

HttpContext.Current.Session["UserID"] in the list endpoint. The existing

JwtSessionFilter is therefore expected to authenticate the JWT and populate

the required Session values before the action executes.

No explicit role authorization is implemented for approve, reject, or delete.

Although the list endpoint has special Branch Executives filtering, there is

no code restricting approve/reject/delete to a specific role.

2. Professional Student Approval Grid / List

=========================================================

Endpoint:

GET /api/professional-student-approval/list

Purpose:

Returns the list of active Professional Students available for the approval

grid.

The endpoint retrieves ProfessionalStudents where Status = 1 and joins

multiple master tables to return descriptive values such as district,

gender, caste category, occupations, area type, course type, and college

type.

For authenticated users whose role is "Branch Executives", the results are

restricted to districts assigned to that authenticated user through

BranchExecutiveDistrictMapping.

Content-Type:

No request body is required.

Authorization:

JWT Required

Authorization Header:

Authorization: Bearer <JWT\_TOKEN>

JWT / Authorization Details:

\* JWT Required: Yes

\* Filter/Authorization Scope: Action-level

\* Existing authorization attribute: [JwtSessionFilter]

\* Required Claims: Not directly read from JWT claims in this controller.

\* Required Session Values:

- UserID

- UserRole

\* Required Roles: No single role is mandatory for access to the endpoint.

\* Special role behavior:

- If UserRole = "Branch Executives", district filtering is applied.

- Other authenticated roles are not explicitly rejected by this action.

\* How identity is used:

- Session["UserID"] is converted to an integer and used as @UserId

when the authenticated role is "Branch Executives".

- Session["UserRole"] determines whether Branch Executive filtering

is applied.

\* JWT-to-Session dependency:

The controller expects the existing JwtSessionFilter to populate

HttpContext.Current.Session["UserID"] and

HttpContext.Current.Session["UserRole"].

Authentication failure behavior implemented by the controller:

\* If Session["UserID"] is missing:

401 Unauthorized

\* If Session["UserID"] cannot be converted to a positive integer:

401 Unauthorized

Important:

The controller does NOT explicitly return 403 Forbidden for users with

other roles. There is no explicit role whitelist.

\* The JwtSessionFilter is responsible for authentication before the action

executes.
